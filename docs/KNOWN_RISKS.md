# PactPay Arena — Known Risks

Severity: **H** = can sink the demo or violate a security invariant; **M** = degrades quality; **L** = nuisance. Status as of 2026-10-11 (pre-implementation).

> **Historical register.** This list was written before the code existed and is kept as the original risk analysis; several rows (for example R16 and R19) describe a state that has since changed. For the current picture read [SECURITY_REVIEW.md](SECURITY_REVIEW.md), [QA_REPORT.md](QA_REPORT.md) section 6 and [RELEASE_CANDIDATE.md](RELEASE_CANDIDATE.md) section 6.

## Access / external dependencies

| #   | Risk                                                                                | Sev | Mitigation                                                                                                                                                                                                               |
| --- | ----------------------------------------------------------------------------------- | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1  | No PayPal sandbox credentials present; P0 requires a working sandbox flow           | H   | User creates sandbox REST app + business and personal sandbox accounts. Build behind a `PaymentProvider` interface with a clearly labeled test double so non-payment work proceeds. Never claim success from the double. |
| R2  | No AI API key present                                                               | M   | Deterministic scripted agent fixtures are required by the constitution anyway; live model is optional, behind an interface.                                                                                              |
| R3  | Webhooks need a public HTTPS endpoint on port 443; localhost can't receive them     | H   | Decide hosting/tunnel early; webhook work (P1) needs a deployed or tunneled URL and a real webhook ID. Simulator mock events use `WEBHOOK_ID` and only support offline verification.                                     |
| R4  | AG Grid Enterprise, Integrated Charts and AG Studio are commercial; no keys present | M   | Use Community Grid/Charts for P0/P1. AG Studio is P2 only, via 45-day trial; check trial expiry vs. judging date. Unverified whether AG Studio needs Grid Enterprise.                                                    |
| R5  | Payouts API: live-account approval and scopes unverified                            | M   | Per constitution, keep payout separate from capture; ship a loudly labeled simulation unless sandbox Payouts is confirmed working.                                                                                       |
| R6  | Multi-party payee routing in Orders may need partner approval                       | M   | Assume single sandbox merchant payee; model "seller" as a catalog/payee record validated server-side.                                                                                                                    |

## Payment correctness (PayPal semantics not yet verified)

| #   | Risk                                                                                                                                                                                                                                                                                                         | Sev | Mitigation                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R7  | **Partly resolved 2026-10-11** from PayPal's OpenAPI spec: 3-day honor period, capturable up to 29 days, reauthorize needed after honor period, `final_capture` exists, no `EXPIRED` authorization status (ARCHITECTURE §2.1). **Still open:** expiry can't be observed in sandbox within project time (A6). | M   | Expiry logic tested with an injected clock only; documented as unverified against PayPal.                                                                            |
| R8  | `PayPal-Request-Id` is a defined header on create/authorize/capture/void (verified); retention window and replay-with-different-body behavior are undocumented (A2)                                                                                                                                          | M   | Local unique constraints + GET-before-retry are primary; PayPal idempotency is secondary.                                                                            |
| R9  | Mis-labeling authorize→capture as "escrow"                                                                                                                                                                                                                                                                   | H   | Copy/UI review: say "authorize then capture", never "escrow".                                                                                                        |
| R10 | Pending/failed/unknown payment shown as success; AI text treated as proof of payment                                                                                                                                                                                                                         | H   | UI state derives only from server-verified PayPal responses/verified webhooks; test for it.                                                                          |
| R11 | Replay / duplicate capture / duplicate webhook processing                                                                                                                                                                                                                                                    | H   | Persisted idempotency keys, state-machine guards, unique constraint on PayPal event ID.                                                                              |
| R12 | Webhook signature verification mistakes (re-serialized body, trusting `cert_url` host, wrong webhook ID source)                                                                                                                                                                                              | H   | Verify against raw body; allow-list PayPal cert hosts; webhook ID from server config. Prefer offline verification; postback as fallback (must send body byte-exact). |
| R13 | Floating-point money                                                                                                                                                                                                                                                                                         | H   | Integer minor units end to end; PayPal's decimal strings parsed/formatted by one module; lint/test for `parseFloat` on amounts.                                      |

## Security

| #   | Risk                                                                     | Sev | Mitigation                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------ | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R14 | Prompt injection via seller messages bypasses the protected buyer        | H   | Policy engine is sole authority; model output is advisory and Zod-validated; adversarial fixture suite asserts model-recommended violations are still blocked.                                        |
| R15 | Agent mutating the user's mandate                                        | H   | Mandate is versioned, immutable to agent code paths; no agent-callable write API.                                                                                                                     |
| R16 | Secrets in source/logs/browser                                           | H   | `.env.local` gitignored, `.env.example` placeholders only, server-only modules, log redaction. **No `.gitignore` exists yet and repo is not under git** — create both before any credential is added. |
| R17 | Locally generated hash chain mistaken for external proof of authenticity | M   | Document it as tamper-evidence of local log only; PayPal IDs/verified webhooks are the external evidence.                                                                                             |
| R18 | Vulnerable baseline agent perceived as real unsafe behavior              | M   | Sandbox/simulated only, "INTENTIONALLY UNSAFE BASELINE" label in UI and docs.                                                                                                                         |
