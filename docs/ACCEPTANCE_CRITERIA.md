# PactPay Arena — Acceptance Criteria

How to read this: each criterion is testable and has **evidence** that must exist before it is claimed. Nothing is "done" until the evidence is produced by a real run; this document defines the bar, it does not report results. Design context: [ARCHITECTURE.md](ARCHITECTURE.md), [TRANSACTION_STATE_MACHINE.md](TRANSACTION_STATE_MACHINE.md), [THREAT_MODEL.md](THREAT_MODEL.md).

Tags: **[PP]** needs PayPal sandbox credentials (blocker B1); **[PUB]** needs a public HTTPS 443 URL (blocker B2); **[LLM]** optional live model (never required for acceptance). Criteria without a tag must pass offline with the `SimulatedLedger` and scripted agents.

Priority: **P0** = demo cannot ship without it · **P1** = strongly expected, cut only per the cut line · **P2** = only after P0/P1 are green.

## 0. Global gates (apply to every task)

| ID  | Gate                                                                                                             | Evidence                                                                                                          |
| --- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| G-1 | `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` all exit 0 on a clean checkout (`npm ci` first) | Command output pasted in the task report                                                                          |
| G-2 | No secret in the repo or in a client bundle; `.env*` ignored; `.env.example` has placeholders only               | Secret-scan script output; grep of `.next` client chunks for `PAYPAL_CLIENT_SECRET` value pattern returns nothing |
| G-3 | No test is skipped/disabled/weakened to make a check pass                                                        | Diff review; `it.skip`/`.only` lint rule                                                                          |
| G-4 | Any behavior not verified (external, expired-honor-window, etc.) is stated as unverified in the report           | Report "Unverified assumptions" section                                                                           |

## 5. Demo-day checklist (all must be true to present as "working")

1. Scripted Arena replays S1–S9 offline; protected pane shows zero cap violations.
2. One recorded, real PayPal Sandbox authorize→capture and authorize→void with ids in `EVIDENCE.md` (**[PP]**).
3. Unknown/pending states demonstrably render as non-success (fault-injected).
4. Webhook verification shown with a real sandbox event, or the demo says plainly that it was only unit-tested (**[PUB]**).
5. Limitations slide/section: no escrow; payout simulated; honor-period expiry tested with a fake clock only; shared-passcode auth is demo-grade.
